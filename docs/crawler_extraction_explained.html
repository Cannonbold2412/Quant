How the Crawlers Extract Info

AQRL aqrl/librarian/ + orchestration/handlers/librarian.py — Stage 10 “Librarian & Curiosity Engine”. Pure Python collectors (Claude never crawls), one uniform pipeline for every source.

1 · The Big Picture — end-to-end pipeline

Two jobs do the work: COLLECT_PAPERS (pure Python, zero LLM cost) and EXTRACT_KNOWLEDGE (the only place an LLM touches a document). A third job, COLLECT_MARKET_DATA, is not a crawler at all — it just reads freshness stats over already-ingested data snapshots.

1 Search-term derivation handlers/librarian.py :: _search_terms_for_question Open research_questions? Use each one's stored search_terms, else derive top-6 keywords from the question text (relevance.keywords()). No open questions → broad sweep with configured librarian_broad_terms. This is the “curiosity loop” targeting mode.
↓one search per question (or one broad search)

Then follow each hit to arxiv.org/html/<id> for full sectioned text; fall back to abstract if no HTML rendering exists.
2b FeedCollector collectors.py :: FeedCollector.search One RSS/Atom reader over configured feed URLs (SSRN, blogs, journals — same code path, different config). Parse every <item>/<entry>, then relevance-gate BEFORE fetching the body: if title+summary scores 0 vs terms, the item is never downloaded.

3 Fetch layer (polite HTTP) fetch.py :: UrllibFetcher Stdlib urllib.request only — no httpx/feedparser/bs4 dependency. Per-host throttle spaces requests by librarian_min_request_interval_seconds. Custom User-Agent, configurable timeout, failures raise FetchError which collectors swallow as “fewer results.”
↓XML / HTML bytes
4 HTML → Markdown-flavoured text html_text.py :: html_to_text html.parser.HTMLParser event walk: headings become ATX markers (#, ##…), block tags become paragraph breaks, chrome dropped. Output looks like native Markdown so downstream chunking has exactly one code path.
↓clean text per document
5 Dedup + cheap relevance gate handlers/librarian.py :: run_collect Content hash — skip if seen this run or already in external_documents (“read once, ever”). Then term-overlap relevance on title + first 2000 chars. Near-free by design — rejects obviously-irrelevant docs before any LLM cost.
↓survivors
6a Archive raw text to disk _archive_raw_text documents/<content_hash>.txt — idempotent side effect, safe outside the job's write lock.
6b Persist + route persist_collect Insert into external_documents: relevance ≥ threshold → status pending + emit DOCUMENT_INGESTED; else irrelevant (kept, not dropped, so the filter stays auditable).
↓EXTRACT_KNOWLEDGE job per relevant document
7 Structural chunking chunking.py :: chunk_by_structure Never a blind token window. Rule 1: split at detected headings (ATX #, setext underlines, numbered titles like 2.1 Method). Rule 2: sections still > max_chars=4000 fall back to greedy whole-paragraph accumulation — cuts only at blank lines, never mid-equation.

↓claims_by_chunk

↓

2 · The fetch layer — polite-by-default HTTP

The only outbound-HTTP code in the codebase. Everything sits behind a Fetcher Protocol so tests use StubFetcher — pre-supplied bytes keyed by exact URL; no test ever touches the network.

MechanismWhat it doesWhere
Per-host throttlingA process-wide _last_request_at: dict[host, timestamp]. Before each GET it sleeps the remainder of the minimum interval since that host's last request. A collector sweeping many arXiv pages in a loop can't hammer the host even if it forgets to pace itself.UrllibFetcher._throttle
HeadersConfigured User-Agent; optional Accept per call — application/atom+xml for the arXiv API, text/html for full-text pages, mixed RSS/XML accepts for feeds.UrllibFetcher.get
Failure contractNetwork errors / timeouts raise FetchError. Collectors treat that as “return fewer results, never raise” — one dead feed must not kill a multi-source run.fetch.py:70, collectors.py:139, collectors.py:199
def _throttle(self, host):
    last = self._last_request_at.get(host)
    if last is not None:
        wait = self._min_interval - (time.monotonic() - last)
        if wait > 0:
            time.sleep(wait)          # space out same-host requests
    self._last_request_at[host] = time.monotonic()

3 · The two collectors

ArxivCollector — query API, then chase full text

  • Each entry yields CollectedDoc(source="arxiv", source_id=arxiv_id, url="https://arxiv.org/abs/<id>", …).
  • Multiple authors joined via _authors_of (arXiv carries one <author> per person).
  • A failed full-text fetch degrades gracefully to abstract — the hit is kept either way.
  • XML parsing matches tags by local name (tag.rsplit("}", 1)[-1]) so namespaces never break matching.

FeedCollector — gate first, fetch second

This ordering is the key economy trick of the feed path: the network-bound part of collection spends bandwidth only on plausibly-relevant items. One shared parser (_parse_feed_items) handles both RSS and Atom by iterating every element whose local name is item or entry, extracting title / description-or-summary / link / pubDate-published-updated / author generically.

4 · HTML → text — two-tier normalization

When the optional extraction extra is installed (pip install aqrl[extraction] → trafilatura, Apache-2.0), its main-content algorithm strips boilerplate the stdlib parser keeps — menus, cookie banners, related-posts chrome. Without it (or on any failure/empty result), the built-in stdlib parser handles every input, which is why no test requires trafilatura to be present.

Heading preservation trick: trafilatura flattens <h1>–<h4> into plain body text, which would cost chunk_by_structure every section boundary. So html_text.py pre-transforms each heading into a paragraph carrying an ASCII sentinel (@H2@ Method), lets trafilatura run, then maps surviving sentinel lines back to ATX markers (## Method). Verified: headings survive, nav chrome does not.

Config: output_format="markdown", include_formatting=True, include_tables=True, include_images=False, include_links=False. Tiny/degenerate inputs (< main-content threshold) automatically degrade to the stdlib tier.

h1–h4 → #…#### heading lines p · div · section · article · li · br · tr · blockquote → blank-line paragraph break script · style · nav · header · footer · noscript — skipped entirely (skip-depth counter handles nesting) 
class _TextExtractor(HTMLParser):
    def handle_starttag(self, tag, attrs):
        if tag in _SKIP_TAGS: self._skip_depth += 1; return
        if self._skip_depth: return              # inside dropped chrome
        if tag in _HEADING_TAGS:
            self._heading_prefix = _HEADING_TAGS[tag]  # remember "#" level
        elif tag in _BLOCK_TAGS:
            self._parts.append("\n\n")                 # paragraph break

    def handle_data(self, data):
        if self._skip_depth: return
        if self._heading_prefix is not None:
            # only the FIRST data run inside a heading gets the marker:
            self._parts.append(f"{self._heading_prefix} {data.strip()}")
            self._heading_prefix = None
        else:
            self._parts.append(data.strip() + " ")

Post-processing collapses runs of blank lines so output is clean paragraphs separated by exactly one blank line. Character refs are decoded automatically (convert_charrefs=True).

Relevance score — how it actually works

# tokenize lowercase [a-z0-9], drop stopwords ("the","paper","method",…) and words len ≤ 2
hits   = sum(1 for t in query_terms
             if any(t in dt or dt in t for dt in doc_terms))
return hits / len(query_terms)          # bidirectional substring match!

Note the bidirectional substring check ("momentum" inside "momentums" counts) — crude but intentionally simple. Its only job: separate “plausibly about the right topic” from “clearly not” before anything expensive runs. The same module's keywords() derives search terms from a research question: top-6 most frequent non-stopword terms, ties broken by first appearance.

6 · Chunking — structure first, never a blind window

The motivating rule (TRD §12.2): “a blind token window risks cutting an equation across a boundary.”

Overlap resolution: heading candidates from all three regex patterns are pooled, sorted by position, and overlapping spans keep whichever starts first — a setext match landing inside an accepted ATX heading is dropped rather than double-counted. Edge cases: empty input returns []; a short headingless doc returns a single chunk titled None; a section body with zero paragraph breaks comes back as one span (the only alternative would be the mid-token cut this module exists to avoid).

7 · EXTRACT_KNOWLEDGE — where the LLM finally reads

Idempotency first: the very first move of run_extract checks extraction_status — if it's already done or irrelevant, return stale. A document is read exactly once, ever.

Pass 1 (per chunk): assemble_chunk_brief(document, chunk) → session.extract_chunk(...) → list of factual claims per chunk. Tokens accumulate.

Pass 2 (synthesis): all chunks + their claims → session.synthesize(...) → a few distinct ProposedExternalKnowledge ideas, each citing source-chunk indices plus layer, category, applicable markets/timeframes, strengths/weaknesses, required operators, proposed experiments, extraction confidence.

Validation: cited chunk indices outside [0, len(chunks)) are dropped, never guessed.

Closing the curiosity loop: if the document came from a research question, record_answer(origin_question_id, knowledge_ids) links the extracted ideas back to the question that motivated the search.

8 · Design properties worth remembering

PropertyHow it's achieved
Claude never crawlsCollectors are pure Python; the LLM only sees text that already passed the cheap gates.
Read-once guaranteeContent-hash dedup in collect + status check in extract — no document is fetched-then-re-extracted across runs or jobs.
PolitenessCentralized per-host throttle inside the one fetcher object, not left to each collector.
Fault isolationEvery fetch/parse failure collapses to “fewer results” — a dead feed never aborts a multi-source run; failed full-text falls back to abstract/summary.
AuditabilityIrrelevant documents are stored (status irrelevant) rather than deleted, so the relevance filter can be calibrated against what it rejected.
Testability without networkStubFetcher, session overrides (set_session/set_embedder/set_fetcher) — heavy run() half is side-effect-free on the DB, persist() half is atomic.
Budget disciplineZero tokens for collection; extraction token spend charged to the global daily budget via budget_consume.
